# v0.6.2 - Fix Release with assets & regenerated C

Re-release de **v0.6.1**: no cambia el código del port. La v0.6.1 publicada en GitHub estaba **rota**
(el juego se comportaba "como una versión anterior a 0.5.0") aunque el **build local fuese correcto**.
La causa eran dos cosas del **empaquetado/CI**, no del port.

## `assets/` y `saves/templates/` ya van en el paquete

El paso *Empaquetar* de `ci.yml` copiaba solo el `.exe`, las DLLs, los textos legales y la carpeta
`rom/`. Faltaban los datos que el ejecutable busca **junto a sí**:

- `assets/lang/*.txt` → sin traducciones
- `assets/logos/*.png` → sin logos HD de la intro
- `assets/sounds/*.wav` → sin SFX del menú
- `saves/templates/*` → `EXTRAS > ELEGIR NIVEL` sin plantillas
- `licences/OFL.txt` → licencia de la fuente Work Sans

Fix: **fuente única** `tools/package_release.py` (el mismo subconjunto que copia el `POST_BUILD` de
CMake), invocada por los jobs `windows` y `linux`, para que CI y build local sirvan los mismos datos.

## El binario ya incluye el C recompilado con el fix de #14

El CI no versiona el C recompilado (ADR 0009) y lo clona de un **repo privado de secretos**. Ese repo
seguía con el `RecompiledFuncs` del **2026-09-21**, anterior al fix de *jump tables* (`f13bc68`, #14):
la release compilaba con el `switch` truncado de `func_8035A3D8` y los crashers de ataque a distancia /
veneno seguían, mientras el build local (que usa `build/recomp` ya regenerado) iba. Fix: publicado el
`RecompiledFuncs` regenerado (6 ficheros; **11 funciones / 73 entradas**).

> Corrige la hipótesis del handoff: los **forks no eran el problema**. rt64 `a8f0a70`, N64ModernRuntime
> `a11fbf2` y N64Recomp `cab94d9` están publicados y se resuelven por SHA en un clon limpio (verificado).

## Dependencias

Sin cambios: rt64 `a8f0a70`, N64ModernRuntime `a11fbf2`, N64Recomp `cab94d9`.

`saves/templates/`; el asset de Release es el zip interno (sin anidar); guardado (`.pak`) y
veneno/ataque a distancia (#14) OK.

# v0.5.1 - Clean release: no diagnostic dumps by default

El `.exe` de release **ya no deja ficheros de volcado** en su carpeta. Todos los diagnósticos que
escribían en disco pasan a ser **opt-in** (desactivados por defecto; el código se conserva para
cuando haga falta depurar).

## Qué cambia

- **Solo `hh.log`** se escribe siempre (y se **sobrescribe** en cada arranque); recoge el flujo y los
  errores para diagnóstico.
- Pasan a estar **desactivados por defecto** (antes algunos se escribían siempre):
  - `hh_audio.log` (audio), `hh_tick.log` / `hh_slow.log` (cadencia de tick), `hh_state.log` /
    `hh_slice.log` / `hh_hang*.log` / `hh_flag.log` (watchdog de cuelgue) y los volcados de crash
    `hh_crash.log` + `hh_crash_rdram/dmem_*.bin`.
  - `hh_pak.log` (diagnóstico del Controller Pak, en el runtime).

## Cómo volver a activarlos (depuración)

- `HH_DIAG=1` — diagnósticos de audio/tick y el watchdog de cuelgue.
- `HH_CRASH_LOG=1` — volcados de crash (`hh_crash.log` + RDRAM/DMEM).
- `HH_PAKLOG=1` (o una ruta) — log del Controller Pak.
- Los que ya eran opt-in (`HH_HUD_TRACE`, `HH_MENUTRACE`, `HH_REPLAYLOG`, `HH_FRAMELOG`,
  `HH_DUMP_RDRAM_AT`, etc.) no cambian.

Sin variables de entorno, un arranque normal solo produce `hh.log`, `config.ini`, `saves/` y `cache/`.

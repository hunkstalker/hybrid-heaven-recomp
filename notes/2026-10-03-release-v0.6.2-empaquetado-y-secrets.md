# Release v0.6.2 — empaquetado sin assets y C recompilado obsoleto (2026-10-03)

> Sesión sobre `main` (v0.6.1 + handoff). Objetivo: lanzar v0.6.2 porque la release v0.6.1 de GitHub
> está rota. Se distingue **medido** de **inferido**. Detalle previo: §7 de
> `notes/2026-10-03-fps-tagging-dobj-y-handoff.md`. La rama `fps-interpolacion-tagging` no se toca.

## 0. Resumen

- **Medido**: el `.zip` de la v0.6.1 **no incluye** `assets/` ni `saves/templates` ni `licences/`
  (listado del ZIP descargado). Es el bug seguro de empaquetado.
- **Medido**: los **forks no son el problema**. Los pins (`runtime.lock` + gitlinks) apuntan a
  `rt64 a8f0a70`, `NMR a11fbf2`, `N64Recomp cab94d9`, y los tres **se resuelven por SHA** en un
  `git fetch --depth 1 <url> <sha>` (hecho con los tres remotos). La hipótesis "forks viejos" del
  handoff queda **descartada**.
- **Medido (causa real del #14/veneno)**: el **repo privado de secretos** (de donde CI clona el C
  recompilado, ADR 0009) seguía en el `RecompiledFuncs` del **2026-09-21**, **anterior** al fix de
  jump tables del #14. El `func_8035A3D8` del secrets tenía `case 0/1` + `switch_error`; el
  `build/recomp` local (regenerado 2026-10-02) tiene los 9 casos. Solo **6 ficheros** difieren.
- **Inferido (fuerte)**: por eso la release compila el switch truncado → #14/veneno siguen rotos en el
  binario de GitHub aunque el port sea v0.6.x y el build local vaya.

## 1. Reproducción (medido)

- ZIP v0.6.1 descargado (`HybridHeavenRecomp-Windows.zip`, 18.0 MB). Contenido: `Hybrid Heaven
  Recomp.exe`, `SDL2.dll`, `dxcompiler.dll`, `dxil.dll`, `LEEME/CREDITOS/LICENCIA`, `rom/`. **Sin
  `assets/`, `saves/`, `licences/`**.
- Strings del `.exe`: contiene marcadores del fork NMR (`STATEXP`, `[ROW]`, `hh_pak`, `get_function`,
  `switch_error`, "jump table") → **sí** compila con el runtime del fork, no con upstream. No contiene
  los marcadores de la rama fps (`[hh-pair]`, `unpaired`, `func_8000C768`), coherente con `main`.
- Forks: `git ls-remote` + `git fetch` por SHA de `a8f0a70` (rt64) y `a11fbf2` (NMR) OK; `cab94d9`
  (N64Recomp) es la punta publicada de `fork/hybrid-heaven`. → **no hay que pushear forks**.
- Secrets: `/app/hh-recomp-secrets` en `8d205a5` (2026-09-21), en sync con su `origin/main` conocido.
  `diff -rq` contra `build/recomp/RecompiledFuncs` (2026-10-02): difieren `funcs_0, 54, 59, 61, 62, 73`;
  todas las diferencias son **casos de jump table que faltaban** (`LOOKUP_FUNC` vs `switch_error`).

## 4. Lecciones

- El "build local va y GitHub no" puede ser **dos** fallos de entorno distintos: datos no empaquetados
  **y** C recompilado no re-publicado. No atribuirlo a los forks sin comprobarlos (los pins eran
  correctos).
- Publicar el `RecompiledFuncs` al repo de secretos es **paso manual** (`docs/workflows.md` §1): si se
  regenera por un fix (p.ej. #14), hay que pushearlo o el CI seguirá compilando el C viejo.
